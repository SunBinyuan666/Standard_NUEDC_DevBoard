## 1. 概述与总体原则

### 目的
- 统一个人嵌入式编程行为，促进文档规范化标准化
- 培养严谨务实的工作作风，提高效率和开发成功率
- 对齐功能安全标准（IEC61508、ISO 26262）

### 三大原则

#### 清晰第一
- "程序必须为阅读它的人而编写，只是顺便用于机器执行"
- 可阅读性 > 性能（仅确定性能是瓶颈时才主动优化）

#### 简洁为美
- 易于理解且易于实现
- 废弃代码及时清除，重复代码提炼成函数

#### 风格适宜性与一致性
- 修改他人代码时遵循现有风格
- 部分内容参考 KR 风格但适度修订

### 术语定义
| 术语 | 含义 |
|------|------|
| **原则** | 必须坚持的指导思想 |
| **规则** | 强制必须遵守的约定 |
| **建议** | 必须加以考虑的约定 |

### 适用范围
所有基于C语言的嵌入式固件开发项目（MCU、DSP、RTOS应用层）

## 2. 文件结构

### 2.1 文件概述及版本信息（每个文件开头必须包含）

```c
/***********************************************************************************
 * @file      usart.c
 * @author    Sunbinyuan（EEE2409036@xmu.edu.my）
 * @version   V1.3.0
 * @date       2023-04-18
 * @brief     usart模块函数
 *
 * @history   V1.3.0 兼容支持STM32 F1xx和F4xx              ---2023-04-18
 *            V1.2.0 重新整理排版，把串口打印信息提拉出来    ---2022-01-11
 *            V1.1.0 增加UARTx_ACK函数                      ---2021-04-03
 *            V1.0.0 首版usart模块函数                      ---2018-06-08
 **********************************************************************************/
```

**必须包含：** 文件名、作者、版本、日期、概述、版本履历

### 2.2 头文件的结构（六部分）

```
1. 文件开头的概述及版本信息
2. 预处理块 (#ifndef/#define/#endif)
3. 包含的头文件（标准库 -> 平台库 -> 本工程）
4. 类型声明 (typedef/struct/enum)
5. 宏声明 (#define)
6. 函数声明 (extern函数原型)
7. 变量声明（禁止在头文件中定义变量！）
```

**示例：**
```c
#ifndef GPIO_H
#define GPIO_H

/* Includes ------------------------------------------------------------------*/
#include <stdint.h>   /* 标准固定宽度整数类型 */
#include "platform.h"

/* Types ---------------------------------------------------------------------*/
typedef struct {
    uint16_t pin;
    uint8_t  mode;
} GPIO_InitTypeDef;

/* Macros --------------------------------------------------------------------*/
#define GPIO_PIN_MAX    16U

/* Function Prototypes -------------------------------------------------------*/
void GPIO_Init(GPIO_InitTypeDef *init);
uint8_t GPIO_ReadPin(uint16_t pin);

#endif /* GPIO_H */
```

**关键规则：**
- 【规则2-2-1】用 `#ifndef/#define/#endif` 防止重复引用
- 【规则2-2-2】`<xxx.h>` 引用标准库，`"xxx.h"` 引用非标准库
- 【建议2-2-1】头文件只放"声明"不放"定义"
- 【建议2-2-2】不提倡 `extern int value` 全局变量声明
- 【建议2-2-3】头文件按"标准库->平台库->本工程"顺序包含

### 2.3 源文件的结构（六部分）

```
1. 文件开头的概述及版本信息
2. 头文件包含
3. 本文件私有宏声明 (#define)
4. 本文件私有类型定义 (typedef)
5. 本文件私有变量声明 (static)
6. 本文件内部函数原型 (static)
7. 程序实现体（函数定义）
```

**示例：**
```c
/* Includes ------------------------------------------------------------------*/
#include "gpio.h"

/* Private defines -----------------------------------------------------------*/
#define GPIO_TIMEOUT_MS  100U

/* Private variables ---------------------------------------------------------*/
static uint32_t s_gpio_init_flag = 0U;

/* Private function prototypes -----------------------------------------------*/
static void GPIO_ClockEnable(uint16_t pin);

/* Functions -----------------------------------------------------------------*/
void GPIO_Init(GPIO_InitTypeDef *init)
{
    GPIO_ClockEnable(init->pin);
    /* ... */
}
```

### 2.4 推荐工程目录结构

```
Project/
├── Doc/           # 文档（规范、设计说明）
├── Drivers/       # 底层驱动（HAL/LL）
│   ├── CMSIS/
│   └── STM32_HAL/
├── Middlewares/   # 中间件（RTOS、协议栈）
├── App/           # 应用层代码（与厂商库严格分离）
│   ├── Inc/
│   └── Src/
├── BSP/           # 板级支持包
└── Build/         # 编译输出
```

## 3. 程序的版式

### 3.1 空行
- 【规则3-1-1】类声明之后、函数定义之后加空行
- 【建议3-1-1】函数体内逻辑密切相关语句不加空行，其他地方加分隔

### 3.2 代码行
- 【规则3-2-1】一行只做一件事（一个变量/一条语句）
- 【规则3-2-2】`if/for/while/do` 自占一行，执行语句不论多少都加 `{}`
- 【建议3-2-1】定义变量时同时初始化

```c
// ✅ 良好
int width;       // 宽度
int height;      // 高度

x = a + b;
z = e + f;

if (width < height)
{
    dosomething();
}

// ❌ 不良
int width, height;
x = a + b; z = e + f;
if (width < height) dosomething();
```

### 3.3 代码行内的空格

| 规则 | 示例 |
|------|------|
| 关键字后留空格 | `if (`, `for (`, `while (` |
| 函数名后不留空格 | `Func(x)` |
| `(){};` 紧贴 | `(x)`, `;` |
| `,` 后留空格 | `Func(x, y, z)` |
| 二元操作符前后留空格 | `=`, `>=`, `<=`, `+`, `*`, `&&`, `\|\|` |
| 一元操作符不加空格 | `!`, `~`, `++`, `--`, `&`(地址) |
| 成员操作符不加空格 | `[]`, `.`, `->` |

### 3.4 对齐
- 【规则3-4-1】`{}` 独占一行，同一列对齐
- 【规则3-4-2】缩进使用 **4个空格**（禁止 Tab）

### 3.5 长行拆分
- 【规则3-5-1】最大长度控制在 **80字符** 以内
- 【规则3-5-2】在低优先级操作符处拆分，操作符放新行首

```c
result = long_variable_a
        + long_variable_b
        + long_variable_c;
```

### 3.6 修饰符位置
- 【规则3-6-1】`*` 和 `&` 紧靠变量名，一行只声明一个指针

```c
/* 推荐 */
uint8_t *p_data;

/* 禁止：y被误认为指针 */
uint8_t *x, y;
```

### 3.7 注释
- 注释是对代码的"提示"，不是文档，不宜过多
- 代码清楚时不必加注释
- 边写代码边注释，修改代码同时修改注释
- 注释准确易懂，避免缩写和二义性
- 位置在被描述代码上方或右方，不可在下方
- 多重嵌套时在段落结束处加注释

```c
/*************************************
* 函数名称 ： Function
* 描述     ： Function demo
* 输入     ： x, y, z 示例参数
* 输出     ： 无
* 返回     ： 无
**************************************/
void Function(float x, float y, float z)
{
    …
}

if (…)
{
    …
    while (…)
    {
        …
    } // end of while
    …
} // end of if
```

## 4. 命名规则

### 推荐命名法：蛇形命名法（snake_case）

| 命名法 | 示例 | 适用场景 |
|--------|------|----------|
| **蛇形 snake_case** | `gpio_read_pin` | 函数名、变量名（**首选**）|
| 大驼峰 PascalCase | `GpioInitTypeDef` | 类型名、结构体名、枚举名 |
| 全大写+下划线 | `GPIO_PIN_MAX` | 宏、枚举常量 |
| 匈牙利命名法 | `U8PinMode` | **不推荐** |

### 4.1 共性规则

- 【规则4-1-1】标识符直观可拼读，望文知意，优先英文单词
- 【规则4-1-2】长度符合"min-length && max-information"，十几个字符不足为怪
- 【规则4-1-3】与平台风格一致（STM32 HAL / FreeRTOS 等）
- 【规则4-1-4】不出现仅靠大小写区分的相似标识符
- 【规则4-1-5】用反义词组命名互斥意义（send/recv, enable/disable, open/close）
- 【规则4-1-6】避免下划线开头及C关键字
- 【建议4-1-1】避免数字编号（Value1, Value2），除非逻辑需要

### 4.2 文件
- 【建议4-2-1】文件名小写+下划线：`gpio_driver.c`, `uart_protocol.h`

### 4.3 宏、常量、枚举
- 【规则4-3-1】**全大写+下划线**
- 【规则4-3-2】宏常量加 `[U]` 或 `[F]` 后缀明确类型

```c
#define BUFFER_SIZE_MAX    256U
#define PI_VALUE           3.14159265F

typedef enum {
    LED_STATE_OFF = 0,
    LED_STATE_ON,
    LED_STATE_BLINK,
} LED_State_t;
```

### 4.4 类型
- 【规则4-4-1】自定义类型用**大驼峰+_t 后缀**

```c
typedef struct {
    uint16_t pin;
    uint8_t  mode;
    uint8_t  speed;
} GPIO_InitTypeDef_t;

typedef enum {
    TIMER_MODE_ONE_SHOT = 0,
    TIMER_MODE_PERIODIC,
} Timer_Mode_t;
```

### 4.5 变量
- 全部**小写+下划线**（名词或 形容词+名词）
- 【规则4-5-1】全局变量加 `g_` 前缀：`uint32_t g_system_tick = 0U;`
- 【规则4-5-2】静态变量加 `s_` 前缀：`static uint8_t s_uart_rx_buf[256];`
- 【规则4-5-3】变量名用"名词"或"形容词+名词"
- 【规则4-5-4】不允许局部变量与全局变量同名
- 【规则4-5-5】**禁止单字节变量名**，仅允许 `i/j/k` 作循环变量
- 【规则4-5-6】`volatile` 变量加 `v_` 前缀：`volatile uint32_t v_isr_tick_count;`

### 4.6 函数
- 【规则4-6-1】全局函数用"**动词**"或"**动词+名词**"：`ADC_GetValue()`, `D0003D_GetVoltageByChannel()`
- 【规则4-6-2】static 内部函数同名规则，无需前缀
- 【规则4-6-3】ISR 加 `_IRQHandler` 后缀：`USART1_IRQHandler(void)`

## 5. 数据类型与安全类型

### 5.1 固定宽度整数类型 —— 强制要求！

【规则5-1-1】**必须使用 `<stdint.h>` 的固定宽度类型，禁止直接使用 `int/long/char`**

```c
/* ❌ 禁止 */
unsigned int counter;
long timestamp;

/* ✅ 推荐 */
#include <stdint.h>
uint32_t counter;
int32_t  timestamp;
uint8_t  byte_data;
```

**对照表：**

| 类型 | 宽度 | 范围 |
|------|------|------|
| `uint8_t` | 8位无符号 | 0 ~ 255 |
| `int8_t` | 8位有符号 | -128 ~ 127 |
| `uint16_t` | 16位无符号 | 0 ~ 65535 |
| `int16_t` | 16位有符号 | -32768 ~ 32767 |
| `uint32_t` | 32位无符号 | 0 ~ 4294967295 |
| `int32_t` | 32位有符号 | -2147483648 ~ 2147483647 |
| `bool` (C99) | 布尔 | 0或1，需 `#include <stdbool.h>` |

### 5.2 布尔类型

【规则5-2-1】使用 `bool` / `true` / `false`，不用 `1` / `0`

```c
#include <stdbool.h>
bool is_initialized = false;

if (is_initialized == true) { /* ... */ }
```

### 5.3 避免隐式类型转换

【规则5-3-1】**显式强制转换**，禁止隐式转换（尤其有符号<->无符号混合运算）

```c
/* ❌ 禁止：隐式转换，-1变为255 */
int8_t x = -1;
uint8_t y = 200U;
if (x < y) { /* 结果不符合预期 */ }

/* ✅ 推荐：显式转换 */
if ((int16_t)x < (int16_t)y) { /* 语义明确 */ }
```

【规则5-3-2】位运算操作数应为**无符号类型**

### 5.4 编译时断言 static_assert（C11）

```c
#include <assert.h>

static_assert(sizeof(CAN_Frame_t) == 8U, "CAN frame size must be 8 bytes");
static_assert(sizeof(uint32_t) == 4U, "uint32_t must be 4 bytes");

/* 不支持C11时的替代方案 */
#define STATIC_ASSERT(cond, msg) \
    typedef char static_assert_##msg[(cond) ? 1 : -1]
```

## 6. 结构体、联合体与枚举

### 6.1 结构体 struct

#### 定义规范
- 【规则6-1-1】必须使用 `typedef`，类型名**大驼峰+_t**
- 【规则6-1-2】成员用**蛇形命名法**
- 【规则6-1-3】成员按从大到小排列（`uint32_t` -> `uint16_t` -> `uint8_t` -> `bool`），减少 padding
- 【规则6-1-4】通信报文结构体必须用 `__attribute__((packed))` 或 `#pragma pack(1)` + `static_assert` 验证大小

```c
/* 推荐：typedef + 大成员在前减少padding */
typedef struct {
    uint32_t counter;   /* 4字节 */
    uint32_t value;     /* 4字节 */
    uint8_t  flag;      /* 1字节 */
    uint8_t  index;     /* 1字节 */
                        /* 2字节padding → 总计12字节 */
} GoodLayout_t;

/* 通信报文：必须packed */
#pragma pack(push, 1)
typedef struct {
    uint8_t  cmd;
    uint16_t payload_len;
    uint8_t  payload[8];
    uint8_t  crc;
} ModbusFrame_t;
#pragma pack(pop)

static_assert(sizeof(ModbusFrame_t) == 12U, "ModbusFrame size mismatch");
```

#### 初始化规范
- 使用 **C99指定初始化器**（Designated Initializer），明确每个成员
- 无法立即赋值时清零：`= {0}` 或 `memset(&var, 0, sizeof(var))`

```c
/* ✅ 推荐：指定初始化器 */
BatteryStatus_t bat = {
    .id           = 1U,
    .voltage_mv   = 3700U,
    .temperature  = 25,
    .is_online    = true,
};

/* ❌ 不推荐：依赖顺序 */
BatteryStatus_t bat = {1U, 3700U, 25, true};
```

#### 使用规范
- 函数参数传结构体用**指针+const**（输入）或**非const指针**（可修改），禁止值传递
- **禁止直接比较两个结构体**（== 不适用，padding不确定），应逐成员比较或 memcmp（仅 packed）

### 6.2 联合体 union

- 用于寄存器位域访问、数据类型转换、省内存
- 类型名以 `_u` 后缀区分
- 位域联合体必须注明硬件含义，使用 `uint32_t` 等无符号类型
- **不建议通过联合体进行类型双关**（未定义行为），改用 `memcpy`
- 为每次使用的"活跃成员"添加注释

```c
/* 寄存器位域访问模式 */
typedef union {
    uint32_t reg;               /* 整字读写 */
    struct {
        uint32_t mode   : 2;    /* [1:0]  GPIO模式 */
        uint32_t otype  : 1;    /* [2]    输出类型 */
        uint32_t ospeed : 2;    /* [4:3]  输出速度 */
        uint32_t pupd   : 2;    /* [6:5]  上下拉 */
        uint32_t reserved : 25; /* [31:7] 保留 */
    } bits;
} GPIO_MODER_u;

/* 类型转换推荐用 memcpy */
float    f_val = 3.14F;
uint32_t u_val;
memcpy(&u_val, &f_val, sizeof(u_val));
```

### 6.3 枚举 enum

- 类型名**大驼峰+_t**，枚举常量**全大写+下划线**
- 第一个成员**显式赋值为 0**
- 末尾添加 `_COUNT` 或 `_MAX` 哨兵值（用于范围检查和数组索引）
- 使用枚举类型而非 `int` 接收枚举值
- switch 枚举时**枚举所有成员 + default 断言**

```c
typedef enum {
    MOTOR_STATE_IDLE    = 0,
    MOTOR_STATE_RUNNING = 1,
    MOTOR_STATE_FAULT   = 2,
    MOTOR_STATE_COUNT,          /* 哨兵值 */
} MotorState_t;

/* 利用_COUNT做范围检查 */
MotorState_t state = get_motor_state();
if (state >= MOTOR_STATE_COUNT) { /* 错误处理 */ }

/* 利用_COUNT定义字符串表 */
static const char *k_state_names[MOTOR_STATE_COUNT] = {
    [MOTOR_STATE_IDLE]    = "IDLE",
    [MOTOR_STATE_RUNNING] = "RUNNING",
    [MOTOR_STATE_FAULT]   = "FAULT",
};

/* switch 必须穷举 */
switch (state)
{
    case MOTOR_STATE_IDLE:    handle_idle();    break;
    case MOTOR_STATE_RUNNING: handle_running(); break;
    case MOTOR_STATE_FAULT:   handle_fault();   break;
    default: ASSERT(false);  break;             /* 非法状态 */
}
```

## 7. C语言模块化封装

### 核心思想
- **高内聚**：同模块功能高度相关
- **低耦合**：模块间依赖少且简单
- **信息隐藏**：内部实现对外不可见
- **接口最小化**：只暴露外部真正需要的接口

### 物理结构：一对 .h/.c 文件

```
uart_driver/
├── uart_driver.h    ← 公共接口（对外暴露）
└── uart_driver.c    ← 实现文件（内部细节）
```

### 职责划分

| 内容 | 放在 .h | 放在 .c |
|------|---------|---------|
| 对外类型定义（typedef/struct/enum） | ✅ | ✗ |
| 对外宏常量（#define） | ✅ | ✗ |
| 对外函数声明（extern原型） | ✅ | ✗ |
| 对外变量声明（extern） | ✅（尽量避免）| ✗ |
| 内部类型/宏 | ✗ | ✅ |
| 函数实现体 | ✗ | ✅ |
| 全局变量定义 | ✗ | ✅ |
| 内部函数（static） | ✗ | ✅ |

### static 信息隐藏

```c
/* uart_driver.c */

/* 私有：外部不可调用 */
static void uart_enable_clock(void)
{
    RCC->APB1ENR |= RCC_APB1ENR_USART2EN;
}

static uint8_t uart_calc_parity(uint8_t data)
{
    /* ... */
}

/* 公共：在 uart_driver.h 中声明 */
void UART_Init(uint32_t baudrate)
{
    uart_enable_clock();
    /* ... */
}
```

### 接口设计原则

- 函数命名：`模块名_动作`（如 `UART_Init`, `UART_Send`）
- 必须提供 `_Init` 和 `_DeInit`，内部维护初始化状态防重复初始化
- 参数和返回值使用模块自定义类型，不暴露内部实现细节

### 依赖方向（单向流动，禁止循环依赖）

```
应用层（App）
    ↓
中间件/服务层（Middleware）
    ↓
驱动层（Drivers/BSP）
    ↓
硬件抽象层（HAL/CMSIS）
```

循环依赖解决方案：引入回调函数（callback）或事件通知机制解耦

### 完整模块化示例：LED控制模块

**led_ctrl.h：**
```c
#ifndef LED_CTRL_H
#define LED_CTRL_H

#include <stdint.h>
#include <stdbool.h>
#include "error_code.h"

typedef enum {
    LED_ID_STATUS  = 0,
    LED_ID_ERROR   = 1,
    LED_ID_COUNT,
} LED_Id_t;

typedef enum {
    LED_MODE_OFF     = 0,
    LED_MODE_ON,
    LED_MODE_BLINK_SLOW,   /* 500ms周期 */
    LED_MODE_BLINK_FAST,   /* 100ms周期 */
} LED_Mode_t;

Error_Code_t LED_Init(void);
void         LED_DeInit(void);
Error_Code_t LED_SetMode(LED_Id_t id, LED_Mode_t mode);
LED_Mode_t   LED_GetMode(LED_Id_t id);
void         LED_Tick(void);   /* 定时器/主循环中周期调用 */

#endif /* LED_CTRL_H */
```

**led_ctrl.c：**
```c
#include "led_ctrl.h"
#include "bsp_gpio.h"

/* 私有类型 */
typedef struct {
    LED_Id_t   id;
    uint8_t    gpio_pin;
    LED_Mode_t mode;
    uint32_t   tick_counter;
} LED_Instance_t;

/* 私有常量 */
static const uint8_t k_led_pins[LED_ID_COUNT] = {
    [LED_ID_STATUS] = GPIO_PIN_5,
    [LED_ID_ERROR]  = GPIO_PIN_6,
};

/* 私有变量 */
static LED_Instance_t s_leds[LED_ID_COUNT];
static bool           s_is_initialized = false;

/* 私有函数 */
static void led_set_physical(uint8_t pin, bool on)
{
    BSP_GPIO_Write(pin, on ? GPIO_PIN_SET : GPIO_PIN_RESET);
}

/* 公共接口实现 */
Error_Code_t LED_Init(void)
{
    if (s_is_initialized) { return ERR_OK; }
    uint8_t i;
    for (i = 0U; i < (uint8_t)LED_ID_COUNT; i++)
    {
        s_leds[i].id           = (LED_Id_t)i;
        s_leds[i].gpio_pin     = k_led_pins[i];
        s_leds[i].mode         = LED_MODE_OFF;
        s_leds[i].tick_counter = 0U;
        led_set_physical(k_led_pins[i], false);
    }
    s_is_initialized = true;
    return ERR_OK;
}

void LED_DeInit(void) { s_is_initialized = false; }

Error_Code_t LED_SetMode(LED_Id_t id, LED_Mode_t mode)
{
    if (id >= LED_ID_COUNT)  { return ERR_PARAM; }
    if (!s_is_initialized)   { return ERR_NOT_INIT; }
    s_leds[id].mode         = mode;
    s_leds[id].tick_counter = 0U;
    return ERR_OK;
}

void LED_Tick(void)
{
    uint8_t i;
    for (i = 0U; i < (uint8_t)LED_ID_COUNT; i++)
    {
        LED_Instance_t *p = &s_leds[i];
        p->tick_counter++;
        switch (p->mode)
        {
            case LED_MODE_OFF:         led_set_physical(p->gpio_pin, false); break;
            case LED_MODE_ON:          led_set_physical(p->gpio_pin, true);  break;
            case LED_MODE_BLINK_SLOW:  led_set_physical(p->gpio_pin, (p->tick_counter % 50U) < 25U); break;
            case LED_MODE_BLINK_FAST:  led_set_physical(p->gpio_pin, (p->tick_counter % 10U) < 5U);  break;
            default: break;
        }
    }
}
```

### 模块化设计检查清单

- [ ] 只有一对 .h/.c 文件，职责清晰单一
- [ ] 所有内部函数已声明为 static
- [ ] 所有内部全局变量已声明为 static 并使用 s_ 前缀
- [ ] 对外类型/宏/函数声明均在 .h 中
- [ ] 变量定义未出现在 .h 中
- [ ] 函数使用"模块名_动作"命名前缀
- [ ] 提供了 _Init 和 _DeInit 函数
- [ ] _Init 内部防止重复初始化
- [ ] 对外接口使用统一错误码类型
- [ ] 无循环依赖，依赖方向单向向下
- [ ] 所有结构体使用指定初始化器初始化

## 8. 表达式和基本语句

### 运算符优先级
- 【规则8-1-1】**用括号确定操作顺序**，不要依赖默认优先级

```c
word = (high << 8) | low;
if ((a | b) && (a & c))
```

### 复合表达式
- 不要编写太复杂的多用途复合表达式
- 不要混淆数学表达式与程序表达式（`a < b < c` 是错的！）

### if 语句 —— 与零值比较规范

| 变量类型 | ✅ 推荐 | ❌ 不良 |
|----------|---------|---------|
| **布尔变量** | `if (flag)` / `if (!flag)` | `if (flag == TRUE)` / `if (flag == 1)` |
| **整型变量** | `if (value == 0)` / `if (value != 0)` | `if (value)` / `if (!value)` |
| **浮点变量** | `if ((x >= -EPSILON) && (x <= EPSILON))` | `if (x == 0.0)` |
| **指针变量** | `if (p == NULL)` / `if (p != NULL)` | `if (p == 0)` / `if (p)` / `if (!p)` |

### for 语句
- 【规则8-4-1】**不可在循环体内修改循环变量**
- 【建议8-4-1】循环变量采用**半开半闭区间**：`for (i=0; i<N; i++)`
- 【建议8-4-2】大循环体内逻辑判断移到外面提高效率
- 【建议8-4-3】最长循环放最内层，最短循环放最外层
- 【建议8-4-4】循环嵌套控制在 **3层以内**

### switch 语句
- 每个 case 结尾必须有 `break`（除非有意重叠）
- **必须保留 `default` 分支**（即使只有 `default: break;`）

### goto 语句
- 少用、慎用，不是禁用
- 合理用途：从多重循环体中跳出（类似楼房着火跳窗）

## 9. 宏、常量、变量

### 常量定义规则
- 【规则】尽量用含义直观的常量代替魔法数字
- C++ 中用 `const` 完全取代 `#define`（有类型安全检查）
- 宏定义表达式必须**完备括号**：`#define RECT_AREA(a, b) ((a) * (b))`
- 多条语句宏用 `do { ... } while(0)`
- **禁止在宏参数中使用自增/自减**（副作用导致多次执行）
- **绝对禁止魔鬼数字**（Magic Number）

### 变量规则
- 【原则】一个变量只有一个功能，不能多种用途
- 【原则】结构功能单一，不要面面俱到
- 【规则】不用或少用**全局变量**（单文件内可用 static 全局变量）
- 【规则】防止局部变量与全局变量同名
- 【规则】通讯结构注意**字节序**（大端/小端）
- 【规则】**严禁使用未初始化变量作为右值**
- 【建议】首次使用前初始化，初始化位置离使用位置越近越好
- 【建议】尽量减少不必要的默认/强制类型转换

## 10. 头文件设计

### 核心原则
- 【原则10-1】头文件放**接口声明**，不放实现
- 【原则10-2】头文件**职责单一**
- 【原则10-3】向稳定方向包含（不稳定→稳定）

### 关键规则
- 【规则10-1】每个 .c 有同名 .h
- 【规则10-2】**禁止循环依赖**
- 【规则10-3】**禁止包含用不到的头文件**
- 【规则10-4】头文件应**自包含**（独立编译通过）
- 【规则10-5】编写 `#ifndef/#define/#endif` 保护符（不以 `_` 开头）
- 【规则10-6】**禁止在头文件中定义变量**
- 【规则10-7】只能通过 include 使用外部接口，**禁止 .c 中 extern 直接引用**
- 【规则10-8】禁止在 `extern "C"` 中包含头文件

## 11. 函数设计

### 核心原则
- 【原则11-1】**一个函数仅完成一件功能**
- 【原则11-2】重复代码提炼成函数（出现两次即考虑，超过三次立刻动手）

### 规则
- 【规则11-1】函数不超过 **50行**（NBNC：非空非注释行）
- 【规则11-2】嵌套深度不超过 **4层**
- 【规则11-3】可重入函数避免共享变量（需共享则用互斥保护）
- 【规则11-4】扇出合理（<7），扇入越高越好

### 参数规则
- 参数合法性检查由**调用者负责**
- 参数书写完整（带名字），无参用 `void`
- 参数命名恰当，**目的参数在前，源参数在后**
- 输入指针参数加 `const` 修饰
- 参数个数控制在 **5个以内**

### 返回值规则
- 不省略返回值类型
- 函数名与返回值语义不冲突
- **正常值和错误标志分开**：正常值用输出参数，错误标志用 return

### 内部实现
- 入口处用 assert 检查参数有效性
- 出口处检查 return 正确性和效率
- **不可返回指向栈内存的指针/引用**

### 断言使用
- 用 assert 捕捉**不应该发生**的非法情况（不是错误处理）
- 在函数入口处 assert 检查参数
- assert **不应产生副作用**

## 12. 内存管理

### 三种分配方式
1. **静态存储区**：编译时分配，程序运行期间存在（全局/static变量）
2. **栈上创建**：函数执行时自动分配释放，效率高但容量有限
3. **堆上分配**：malloc/free 或 new/delete，灵活但问题最多

### 常见内存错误及对策

| 错误 | 对策 |
|------|------|
| 分配未成功就使用 | malloc后立即检查 NULL |
| 未初始化就引用 | 分配后立即赋初值（哪怕清零） |
| 操作越界 | 当心数组下标 ±1 |
| 忘记释放（泄漏） | malloc/free 配对，次数相同 |
| 释放后继续使用（野指针） | free后立即置 NULL |

### 关键规则
- malloc/new 后**立即检查 NULL**
- 数组/动态内存**务必赋初值**
- 避免**下标越界**
- 动态内存申请/释放**必须配对**
- free/delete 后**立即将指针置 NULL**
- **杜绝野指针**：创建时初始化(NULL或合法内存)，free后置NULL

### 指针 vs 数组
- 数组容量固定，指针可变
- 不能对数组名直接复制/比较（用 strcpy/strcmp）
- sizeof(数组)=总字节数，sizeof(指针)=指针变量字节数
- 数组作为函数参数时退化为指针

### 指针参数申请动态内存
- **不能**用一级指针参数申请内存（副本问题）
- 解决方案：指向指针的指针 `**p` 或 函数返回指针
- **不可**返回栈内存指针

## 13. 经验与建议

### const 提高健壮性
- 输入指针参数加 `const` 保护
- 非内部数据类型输入参数用 `const &` 提高效率
- 不修改数据成员的函数声明为 `const` 成员函数

### 效率优化
- 不一味追求效率，正确性/可靠性/可读性优先
- 先优化**数据结构和算法**，再优化执行代码
- 找到瓶颈再优化，不在无关紧要处优化
- 不追求紧凑代码（紧凑≠高效）

### 有益的建议清单
- 当心视觉不易分辨的操作符书写错误（`==` vs `=`, `||` vs `|`）
- 变量创建后及时初始化
- 当心初值/缺值错误、精度不够
- 当心溢出/越界
- 当心忘记错误处理
- 当心文件I/O错误
- 避免技巧性过高代码
- 不设计面面俱到的数据结构
- 优先复用好代码，修补差代码不如重写
- 尽量使用标准库函数
- 编译器设为最严格状态
- 使用 PC-Lint / Logiscope 等工具审查

### 代码质量保证优先级（按重要性排序）
1. **正确性** — 实现设计要求的功能
2. **简洁性** — 易于理解和实现
3. **可维护性** — 可修改能力
4. **可靠性** — 成功运行概率
5. **可测试性** — 发现故障并定位的能力
6. **性能高效** — 少占用资源
7. **可移植性** — 跨环境运行能力
8. **个人方便性** — 个人编程习惯
